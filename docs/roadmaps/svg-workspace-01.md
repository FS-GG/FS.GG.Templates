## Outcome and decisions

A fresh `fable-game` opens a small playable cooperative vector arena, with collectibles, moving obstacles,
interaction, health, score, sound and win/restart. Its production player excludes Studio/laboratory
code. Optional compositions supply integrated Create/Arrange/Play/Review tools, a neutral tactical
planning example and a continuous arcade example. Blank artwork can become a playable, saved, exported
and published game through public package APIs. Clean and upgraded workspaces can complete both a real
routine repair and a semantic rule change under the resolved common policy and specification authority.

Decisions within the accepted contract:

- Retain provider `fable-game`. Introduce a provider/template/wizard **`bundle`** choice with values
  `player` (omitted/default), `studio`, `tactical`, `arcade`, `complete`. `studio` includes the arena and
  integrated tools; `tactical` and `arcade` include their editable example and Studio; `complete` includes
  all examples/tools. Every production player build excludes tools unless explicitly enabled.
  Do not repurpose Rendering's `profile`; reject `bundle` for unrelated providers.
- Product SVG default is a compatible product composition operation under existing lifecycle selection.
  Keep `none`, omitted/explicit `sdd`, explicit `typed-sdd`, and retained `spec-kit` distinguishable.
  Qualify the Quint-backed target explicitly. No lifecycle token alias or coordination activation is implied.
- Keep the existing preview flag readable during a documented compatibility window. An explicit old
  `svgFoundation` selection selects its documented preview-compatible composition; contradictory new/old
  flags refuse before writing. Do not silently reinterpret `svgFoundation=false` as new SVG consent for an
  existing scripted caller. Fresh omission changes only at the new published product release boundary.
- Use existing Rendering scene/workspace/keyboard skills and Game core/Fable/collision/persistence skills
  where their scope fits; add focused assets/performance/replay/rules guidance where absent. Audio owns
  browser-audio guidance and its published bytes. Select skills by actual provider and bundle parameters,
  with explicit negative player tests. Preserve owner identity for the four overlapping Game/Rendering ids.
- Deliver Audio guidance through an Audio-owned skills artifact (a new `FS.GG.Audio.Skills` package if no
  existing published owner artifact satisfies the closed-manifest contract), with SDD owning its transport.
  Do not place independently maintained Audio prose in Game or Templates. Prefer the existing verified
  owner-manifest/materialization machinery over another general plugin subsystem.
- Replace Templates' `fable-remoting` advice with the accepted HTTP-codec boundary, using a documented
  managed-file retirement/rename. Preserve user edits and record conflicts; never delete an edited skill.
- Retain the existing Fable/DOM/Elmish approach and deferred Studio boundary. Do not add React/Feliz to
  the player merely for composition. Record actual bootstrap closure/cost if an existing selected dependency
  requires it. Engine and tool implementation stays package-owned; domain/content/adapters stay editable.

### Bounded authority scope: mandatory versus future

This distinction refines the draft on 2026-09-14; the six milestone identities and .1–.3 ready window
remain unchanged. It does not change the original programme's scope or declare an epoch available.

**Mandatory SVG authority behavior:** each new modeled engine module has its canonical literate Quint
source, explicit supported backend/profile, bindings, assumptions and evidence obligations; generated
artifacts are projections, and current implementation correspondence remains separate from reusable
formal evidence. The generated workspace composes these bounded modules coherently, without hidden
semantic authority in prose or a second interpreter. Clean and upgraded receivers demonstrate actual
routine repair and semantic amendment under published policy/tools/native checks. The §8A installed
F#-v1/profile-1/profile-2/retained-game/external-fixture matrix and failure/rollback cases are mandatory.
An unsupported arbitrary gameplay migration must refuse; universal migration success is not promised.

**Conditional producer seam:** original §8A calls the proposal a “future ChangeProposal” and says a PR
“may carry” its binding/delta “if that producer supports the shape.” Therefore SVG does not require
inventing a public type literally named `WorkspaceModel`, automating proposals for every GitHub issue,
implementing every disposition/semantic-three-way-merge case in SDD #927, or closing that whole issue.
Existing published model/source/binding contracts may satisfy the bounded composition when their actual
expressiveness and freshness checks are demonstrated. A native PR can expose the canonical semantic diff
and current conformance evidence without a new proposal receipt family. If the future producer mechanism
is absent, record the unsupported seam against #927 and do not advertise or emulate it. If a *mandatory*
SVG invariant cannot be represented or validated by existing contracts, identify that exact operation,
diagnostic and receiver case before implementing the smallest SDD-owned addition.

**Next SDD implementation boundary (.2):** qualified skill embedding/materialization, real routine
policy/helper/native-check delivery and guidance precedence, explicit installed Quint backend/profile
author/inspect/provision, and only demonstrated gaps in bounded Fable authority or migration. It does
not include a whole-organization ADR, issue formalization service, global provider migration or lifecycle
default flip. Do not add a new model catalog/schema simply to make its name resemble SDD #927.

**Release D target activation remains real:** original §1 retains D's “promised workspace compatibility
and activation conditions”; the linked revision rationale §3 explicitly says that a result delivered
while the lifecycle/default programme is pending must not be relabeled D. The precise protected condition
is original §8A's later workspace-default flip, grounded in
[ADR-0078](https://github.com/FS-GG/.github/blob/main/docs/adr/0078-github-substrate-v2-new-only-coordination-authority.md):
“The later Typed SDD workspace-default flip is deferred until `OperatingV2`.” This is not a requirement
for every skills release, explicit typed scaffold or SVG **product** default. The bounded later producer
and receiver slice is a supported common Quint-backed base for the targeted Fable family, explicit
legacy-token compatibility/migration, and qualified omitted-default adoption when that epoch exists.
It need not wait for unrelated providers or every historical repository to migrate, nor for every-issue
ChangeProposal automation; it must not claim the sole-lifecycle/default effect before the actual common
base, migration and epoch conditions pass. Keep that effect with SVG-RELEASE-D's activation window.
