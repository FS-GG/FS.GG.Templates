# Held first retained reference rehearsal

The [retained rehearsal controller](../../tests/composition/fable-game/retained-reference-rehearsal.py)
adds a fixed first integration seam for [#4816](https://github.com/FS-GG/.github/issues/4816):
genuinely materialize public Workspace 0.13.0 through installed SDD 2.0.2 with
`typed-sdd`, adopt the published 0.19.3 Complete reference, then perform one locked
restore in the adopted tree. Source delivery leaves `ADMISSION = None` and runs
no runtime. Other cohorts, Fable builds and browser qualification remain open.

The [workflow](../../.github/workflows/retained-reference-rehearsal.yml) is dispatch-only.
It refuses before a delegated unit, private-root creation or acquisition unless
source records the exact owning admission and the first main dispatch binds its
admitted, checked-out and workflow commit identities. The admitted SHA comes from
the actual dispatch and checkout, following the existing maintained pattern;
source does not guess its own future commit. This admission remains separate from
installed-C, custody-pilot and AT grants, whose holds remain unchanged.

## Reused owner and fixed inputs

The controller reuses the actual maintained caller's bounded downloader, archive
readers, clean environment, official SDK acquisition, executable binding and
canonical managed-group executor. It selects only SDK 10.0.401 and the exact
0.13.0/0.19.3 template and SDD 2.0.2 archives and immutable old provider descriptor.
It does not call the full WASM preparation route, install an external Fable,
provision Node/Rust/WASI/browsers or install host packages.

SDK 10.0.401 Linux-x64 URL/SHA512 was selected from Microsoft's official
[10.0 release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json).
The source controller fixes that archive tuple and refuses a changed or ambiguous
selection before downloading its body. Runtime qualification still derives actual
executable/native-member hashes from the verified archive, checks native dependency
resolution and observes the required SDK/runtime versions. Host dependencies remain
host observations; the recorded `ldd` scope does not prove every runtime `dlopen`.

The source-supported401-only order depends on a fresh historical target without
`global.json` in its ancestors, the original 0.13 template having no post-actions,
and SDD 2.0.2 emitting no later SDK process after template creation. Its real CLI
installs and creates the old template before the400-pinned file is delivered.
The transaction then replaces it with the managed401 pin before the first product
restore. No SDK override or temporary pin replacement bypasses an adopted build.
An actual old-product build needs its own400 qualification later.

SDD's declared tool entrypoint, runtime configuration and every installed
`tools/` and `skills/` member are joined to the verified package before its CLI
runs. Generation checks join package product content and identity replacements to
the materialized trees; SDD's hybrid tool manifest and lifecycle provenance retain
separate checks. The reviewed transaction harness runs on copies with authored
sentinels. The real adopted restore uses its current pin and migrated Fable row;
other SDD/Coordination tool rows remain preserved. Lock populations and hashes are
read back after both successful and failed restore attempts.

## Deadlines, retirement and evidence

The workflow allows 35 minutes including checkout/upload. The delegated unit is
bounded at 30 minutes, CPU quota 200%, MemoryMax 8GiB and TasksMax 512. Its properties
are read back before tool provisioning. Setup 720s, materialization 300s and one
restore 480s leave 120s collection, 90s cleanup and 90s overhead. Each phase has an
original absolute cap shared by all its calls; a new call does not renew it.
Runtime admission must still establish actual capacity and the 20GiB staging fit.
These bounds are limits, not observed runtime peaks or evidence of success.

Each fixed command runs as a canonical require-empty group with exact argv,
executable identity, environment keys, cwd and relevant code-input hashes. The
same receipt sequence spans all phases. Download/setup failures block
materialization; materialization failure blocks restore. Original execution
failure and later collection/reporting failures remain separate. The controller
retains bounded metadata, journals, inventories and original managed receipts/logs,
including hidden files. Incomplete collection cannot report a passed rehearsal.

The enclosing unit owns supervisor-death retirement. If the controller or unit
dies before terminal collection, missing terminal custody/evidence remains
Unknown; no successful cleanup is inferred from a stopped watcher or empty later
snapshot. Neither automatic retry nor historical admission replay is selected.

## Pure source preflight

The [pure suite](../../tests/composition/fable-game/test-retained-reference-rehearsal.py)
uses synthetic archives, SDK members, executables and owner receipts, with no
member execution or network. Every fixed synthetic call passes the real canonical
`validate_profile`; no copied validator or silent skip stands in for that contract.
The composition preflight checks out only the pinned owner source, verifies its
45315-byte/SHA256 identity, and runs this suite before SDK setup. It preserves the
existing Python fixture source checkout and all later composition behavior.

Controls cover held-before-write admission, exact source/run bindings, expired
phase/changed-SDK refusals, global/symlink guards, package/installed-member and
post-action checks, setup/materialization/restore/cleanup/collection failures,
original lock readback and bounded evidence. The first composition failure found
that the reused environment already creates `evidence`; the entry now uses its
own `retained-evidence` directory. Pure controls establish source behavior only.
A separately reviewed root admission and genuine original runtime result remain
required before accepting this first seam or the broader retained promise.
