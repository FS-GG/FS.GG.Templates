# SVG authoring generated-candidate boundary

The `fs-gg-fable-game --svgFoundation true` source now has separate player and studio entries. The
player retains the public Preview-A imports and dependency graph. `SvgFoundation/Studio` composes
Rendering's product-neutral scene envelope, descriptors, asset transactions, native studio controls,
packaged Boolean worker and verified Noto resource into a neutral generated example.

`scripts/stage-svg-authoring-candidate.sh` accepts only a
`fsgg.svg-author.rendering-candidate/v1` manifest. It checks the merged Rendering revision, package
IDs, common version, archive hashes, curated Fable interfaces, worker, resources and npm locks before packing `0.11.0-svg-author.1`; the public template and
provider pins remain `0.11.0` and `0.29.0`. The output packet binds both source revisions, all producer
archives, the candidate template archive and payload hashes. Reusing an existing output identity is
refused.

The final qualification restores only those archives into isolated caches, instantiates direct and
SDD 1.7.0 routes, and exercises the retained public 0.11.0 and staged 0.10.0 adopter paths plus the
wizard 0.11.1 two-step path. Browser evidence must cover Chromium, Firefox and WebKit plus a real
keyboard/assistive-technology route. Producer evidence may be reused only when its exact source and
package digests match the supplied packet.

After the Templates source is committed, run the exact closure with:

```bash
SVG_SCENE_ORCA_OBSERVATION=/absolute/generated-studio-orca.json \
  bash tests/composition/fable-game/verify-svg-authoring-candidate.sh \
  /absolute/rendering-candidate /absolute/empty-output
```

The hosted lane independently packs a unique candidate identity from Rendering merge
`ab0de59a5797393f1eaff6dd3146b53ae8bf1a67`, records its archive and payload hashes, and retains that
packet with the generated browser and assistive-technology observations. This avoids assigning the
same package version to archives whose ZIP metadata differs between pack invocations.

The Orca JSON must identify a real process plus successful keyboard selection, property editing and
validation-feedback observations in the generated studio composition.

Workspace adoption changes the bounded managed files listed in
`scripts/apply-svg-foundation-preview.sh`. Collision refusal happens before the backup or destination
is written; interruption rolls back, and explicit rollback restores the original managed bytes.
Authored product files, lifecycle provenance and owner guidance remain outside that list.

Content migration is independent. Preserve original document/catalog inputs and exported SVG while
using Rendering's additive migration. Rolling back packages cannot reinterpret, downgrade or delete a
newer `fsgg.svg-scene/1` file; older tools must report that schema as unsupported. This milestone is a
local-candidate qualification and performs no publication or provider activation.
